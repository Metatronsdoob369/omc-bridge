# v1.0.2 Backlog

Stabilization only. No new features until these gates are automated.

---

## 1. /submit hardening

- [ ] Authentication checks — verify `OMC_SUBMIT_KEY` and `OMC_SUBMIT_HMAC` are enforced, not just warned on
- [ ] Path policy review — audit `ALLOWED_PREFIXES` against actual consumer use cases
- [ ] Safer repo mutation flow — `git stash / pull / stash pop` sequence under concurrent submits

## 2. Release observability

- [ ] Artifact checksum recording — SHA-256 of `dist/index.js` logged in release notes
- [ ] CI failure summary in release notes — surface which job failed if release is triggered against a red commit
- [ ] Artifact verification logs — print file sizes alongside existence checks

## 3. Product polish

- [ ] README API examples — add `curl` request/response pairs for each endpoint
- [ ] Error response consistency audit — ensure all routes return `{ error, code }` shape on failure
- [ ] Env var defaults audit — every env var with a default should have the default documented in `.env.example` and enforced in code

## 4. Regression guardrails

- [ ] Smoke test expansion — add `/escrow/:id/consume` and `/escrow/:id/modules` to the CI smoke job
- [ ] Golden fixture files — extract smoke payloads into `test/fixtures/` so they are versioned and reusable
- [ ] Fresh-install dependency coverage — add a step that greps `src/` for `import` statements and cross-checks against `package.json` dependencies

---

## What is NOT in this backlog

- New endpoints
- New governance logic
- Schema changes
- Infrastructure changes

Those go in v1.1.0 or later. v1.0.2 is stabilization only.
